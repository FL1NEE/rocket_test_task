# Задание 4: Проектирование схемы БД «Тендерная площадка»

PostgreSQL-схема для системы мониторинга госзакупок: `schema.sql` содержит
`CREATE TABLE` для всех сущностей, внешние ключи, индексы и два аналитических
запроса.

## Сущности и связи

```
companies (Компании)
    │ 1
    │
    ├──< tenders (Тендеры)          [customer_id → companies.id]
    │        │ 1
    │        │
    │        └──< lots (Лоты)       [tender_id → tenders.id]
    │                 │ 1
    │                 │
    │                 ├──< bids (Ставки)       [lot_id → lots.id, company_id → companies.id]
    │                 │
    │                 └──1:1 executors (Исполнители)  [lot_id → lots.id UNIQUE, company_id → companies.id]
    │
    └──< bids, executors (компания участвует как заказчик и/или участник/исполнитель)
```

- **companies** — и заказчики, и участники в одной таблице (`company_type`
  различает роль; компания может выступать в обеих ролях).
- **tenders** — публикуются заказчиком, `1:N` к `lots`.
- **lots** — лоты в составе тендера, `1:N` к `bids`, `1:1` к `executors`.
- **bids** — заявки участников на лот, уникальность `(lot_id, company_id)` —
  одна компания подаёт не более одной ставки на лот.
- **executors** — победитель лота с заключённым контрактом; `lot_id UNIQUE`
  гарантирует ровно одного исполнителя на лот.

## Ключевые решения

- `NUMERIC(15,2)` для денег — без потери точности, в отличие от `FLOAT`.
- `CHECK`-ограничения на статусы вместо отдельных справочников — упрощает
  схему для тестового задания; в проде вынес бы в enum-таблицы или `ENUM`-тип.
- Индексы на все FK и на поля, участвующие в фильтрации (`status`, даты).
- Составной индекс `idx_executors_company_date_amount` — покрывающий индекс
  под аналитический запрос №1 (группировка по компании и дате с суммой).

## Аналитические запросы

1. **Топ-3 компании по сумме выигранных тендеров за последний месяц** —
   агрегация по `executors` с фильтром по `contract_date`.
2. **Рейтинг участников по проценту побед (win rate)** среди подавших ≥3 ставок
   за 12 месяцев, с расчётом среднего снижения цены и ранжированием через
   `RANK() OVER (...)`.

## Применение

```bash
psql -U postgres -d tender_platform -f schema.sql
```
